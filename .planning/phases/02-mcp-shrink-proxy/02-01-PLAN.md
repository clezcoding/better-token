## Phase Goal

**As a** developer using an MCP-capable IDE, **I want to** route any MCP server through `better-token` and get smaller tool/prompt/resource descriptions, **so that** I save tokens without breaking tool calls.

<objective>
Deliver the first vertical slice of the MCP shrink proxy: user can start `better-token proxy -- <upstream>` and receive compressed `description` fields on `tools/list`, `prompts/list`, and `resources/list` while `tools/call` and all client→upstream traffic stay untouched.

Purpose: Prove end-to-end IDE↔proxy↔upstream stdio path with L1 compression reused from Phase 1 — the core MCP-01/MCP-02 value.
Output: `@better-token/shrink-mcp` package, `proxy` CLI subcommand, mock upstream fixture, green MCP-01/MCP-02 tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IDE/client → proxy stdin | Untrusted JSON-RPC bytes from local IDE |
| Proxy → upstream child stdin/stdout | Local subprocess; inherits env (D-02) |
| Upstream stdout → proxy → client stdout | Selective mutation only on list-response descriptions |
| Proxy stderr | Human diagnostics only — never mixed into MCP stdout |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Denial of Service | NdjsonReadBuffer | medium | mitigate | Cap accumulated buffer / single line at 4MB; on exceed flush pass-through + stderr warning |
| T-02-02 | Tampering | proxy stdout | high | mitigate | All diagnostics on stderr only; stdout carries only MCP NDJSON lines (D-13) |
| T-02-03 | Tampering | client→upstream pipe | high | mitigate | Never parse stdin; raw pipe only (MCP-02) |
| T-02-04 | Information Disclosure | debug logs | low | accept | Debug optional; local stderr only; no network/telemetry in OSS core |
| T-02-05 | Elevation of Privilege | child_process.spawn | medium | mitigate | spawn with shell:false (default); upstream cmd/args from explicit CLI after `--` only |
| T-02-SC | Tampering | npm installs | low | accept | No new external production packages this phase — workspace link only |

Canon breadcrumb (not minted as prohibition): command-injection via shell spawn is covered by shell:false + /gsd-secure-phase ASVS review.
</threat_model>
