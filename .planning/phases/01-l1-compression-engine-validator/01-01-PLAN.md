<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User CLI args → core engine | Untrusted file path crosses here; path traversal / arbitrary file write risk. |
| Filesystem → core engine | Untrusted file content (rule/memory file) crosses here; prompt-injection-style content + binary/non-markdown rejection. |
| core engine → filesystem (write) | Compressed output crosses here; validator gate is the only thing preventing corrupted output from overwriting the original. |
| npm registry → node_modules | Package install crosses here; [SUS] packages must be human-verified (Task 1). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / Elevation of Privilege | `cli.ts` path handling | high | mitigate | Use Node `fs/promises` only (no shell exec); resolve paths with `path.resolve`; reject paths outside CWD unless explicitly given as an argument; reject non-markdown/binary files (D-19). Plan 03 Task 2 hardens interactive + non-canonical path handling; Plan 01 keeps it minimal but safe. |
| T-01-02 | Tampering | `compressor.compressMarkdown` write path | high | mitigate | Byte-exact validator is a hard pre-write gate; on `ok: false` the compressed output is discarded and the original kept (SAFE-01). Even in `--dry-run` the validator runs and surfaces `validator: fail`. |
| T-01-03 | Tampering / Information Disclosure | Sidecar `<file>.original` | high | mitigate | Create sidecar only when missing, before first successful write; never overwrite an existing sidecar; never write sidecar on `--dry-run` (D-06). Plan 02 implements this; Plan 01 dry-run path writes nothing. |
| T-01-04 | Tampering | Symlink attack on sidecar or target file | medium | mitigate | Use `fs.realpath` before read/write; reject symlinked targets for the sidecar path; size-cap reads to avoid OOM on hostile files. Plan 02 hardens; Plan 01 read-only dry-run. |
| T-01-05 | Repudiation / Information Disclosure | Token figures labeled `estimated` | medium | mitigate | Every CLI token figure is labeled `estimated` (D-09) so users never confuse offline estimates with measured provider usage. Enforced by cli.test.ts assertion on the literal `estimated`. |
| T-01-06 | Tampering | Prompt-injection content in rule files | medium | accept | Compression is deterministic and offline; the engine never executes file content. Heuristics treat content as opaque prose. No mitigation beyond the offline invariant. |
| T-01-SC | Tampering | npm/pip installs (typescript, vitest, tsx flagged [SUS]) | high | mitigate | Blocking `checkpoint:human-verify` (Task 1) before `npm install`; verify publisher + source repo on npmjs.com. All [SUS] packages already audit-approved by researcher; checkpoint is the defense-in-depth gate. |
