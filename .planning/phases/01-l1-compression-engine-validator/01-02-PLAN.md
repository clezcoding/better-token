<objective>
Vertical slice 2: turn the dry-run skeleton into a safe write path. After this plan, a user can run `better-token compress <file>` to actually compress a file on disk, trust that the original is preserved in a `.original` sidecar, re-run safely (idempotent no-op), switch modes by recompressing from the sidecar, and roll back with `better-token rollback <file>`.

This is a vertical slice, not a horizontal "add backup module" task: after Task 1 the user can compress for real and re-run safely; after Task 2 they can roll back and switch modes. The skeleton from Plan 01 already proves dry-run; this plan adds the second user-visible capability (durable, reversible compression).

Purpose: COMP-04 (idempotency) and COMP-05 (backup + rollback) are the trust contract for any real compression. Without them, re-running compression compounds drift and a bad compression cannot be undone.
Output: `compress` write path, `.original` sidecar management, `rollback` command, fixed-point idempotency, mode-switch-from-sidecar.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| core engine → filesystem (write target) | Compressed output crosses here; atomic write + validator gate prevent corruption. |
| core engine → filesystem (write sidecar) | Original content crosses here; never-overwrite invariant protects the true original. |
| filesystem → rollback command | Sidecar content crosses here; symlink + size-cap hardening. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02 | Tampering | `compressFile` write path | high | mitigate | Byte-exact validator is a hard pre-write gate; on `ok: false` no write occurs. Atomic write (temp + rename) prevents half-written targets on crash. |
| T-01-03 | Tampering / Information Disclosure | Sidecar `<file>.original` | high | mitigate | `createSidecarIfMissing` never overwrites an existing sidecar (D-06); `--dry-run` never creates one; backup.test.ts asserts never-overwrite. |
| T-01-04 | Tampering | Symlink attack on sidecar or target | medium | mitigate | `fs.realpath` on parent directory before write; reject symlinked sidecar paths; size-cap reads at 10 MiB. |
| T-01-07 | Denial of Service | Concurrent `compressFile` on same path | medium | mitigate | Atomic rename + fixed-point check: the second writer sees the first's output and no-ops; no corruption. |
| T-01-08 | Tampering | `rollback` overwriting wrong file | medium | mitigate | `rollback` only writes the target path derived from the sidecar; `zod`-validated path argument; no shell exec. |
</threat_model>
