<task type="auto">
  <name>Task 2: Apply branch protection via gh API</name>
  <files></files>
  <action>
Using GitHub CLI against `clezcoding/better-token`, PUT classic branch protection on `main`:

```bash
gh api -X PUT repos/clezcoding/better-token/branches/main/protection \
  -H "Accept: application/vnd.github+json" \
  --input - <<'EOF'
{
  "required_status_checks": {
    "strict": true,
    "contexts": ["build-and-test", "megalinter"]
  },
  "enforce_admins": true,
  "required_pull_request_reviews": {
    "required_approving_review_count": 0,
    "dismiss_stale_reviews": true,
    "require_code_owner_reviews": false
  },
  "restrictions": null,
  "required_linear_history": true,
  "allow_force_pushes": false,
  "allow_deletions": false,
  "required_conversation_resolution": true
}
EOF
```

If API rejects `contexts` (checks never ran), try once with empty contexts + document that contexts must be re-added after first Actions run — OR use the checks array form if documented. Prefer setting contexts now (GitHub allows requiring checks that have not run yet in many cases).

Do not weaken security (no force push, no delete). Solo-friendly: 0 required approvals still forces PR workflow.
  </action>
  <verify>
    <automated>gh api repos/clezcoding/better-token/branches/main/protection --jq '{checks: .required_status_checks.contexts, enforce_admins: .enforce_admins.enabled, allow_force: .allow_force_pushes.enabled, allow_delete: .allow_deletions.enabled, pr_reviews: .required_pull_request_reviews.required_approving_review_count}'</automated>
  </verify>
  <done>GET protection returns non-404; force push disabled; contexts include build-and-test and megalinter (or documented fallback).</done>
